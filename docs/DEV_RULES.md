# 작업 규칙

showpy를 고치는 사람과 AI가 지킬 규칙입니다.

## 대화와 작업

- 한국어 반말로 답합니다.
- 새 기능이나 수정을 부탁받으면 바로 하지 않습니다. 할 수 있는지, 짧은 계획, 예상 시간을 말하고 "시작"이라고 하면 시작합니다.
- 사용자는 코드를 배우는 초보자입니다. 설정 파일, README, 가이드에는 기능마다 쓸 수 있는 값을 실제 코드 예시로, 쉬운 한국어로 적습니다.
- 끝나면 무엇이 바뀌었고, 무엇을 확인했고, 사용자가 무엇을 확인할지 짧게 정리합니다.
- 커밋은 부탁받을 때만 합니다. 메시지는 한국어로 무엇을 왜 바꿨는지 적습니다.
- 시험은 시험 프로젝트에서 합니다. 사용자의 진짜 게임 프로젝트((docs/LOCAL.md에 적힌 것))는 말할 때만 건드립니다.

## 플러그인 수정

- 고친 뒤 반드시 Lint를 돌리고, 화면이 바뀌면 실행해서 확인합니다. 오류가 나면 `traceback.txt`, `errors.txt`, `log.txt`를 읽습니다.
- 플러그인을 바꾼 뒤에는 시험 프로젝트의 `.rpyc`를 지웁니다. 남아 있으면 지운 코드가 계속 실행됩니다.
- init 값 + `init offset`(파일마다 1)이 -999~999 안에 들어야 합니다. `init 999`는 1000이 되어 Lint 경고가 납니다.
- **화면에 보이는 글자에 `·`(가운뎃점), `≡`를 쓰지 않습니다.** 렌파이 기본 한글 글꼴에 없어서 네모로 나옵니다. `,` `/` `=`를 씁니다. (주석, 문서는 괜찮음)
- 화면 글자에 `[`를 쓰면 `[[`로 적습니다.
- 셰이더는 `screen_fx.register_shader`로 등록하고, 투명도를 곱한 색을 맞게 다룹니다(`rgb / a`로 풀고 `vec4(col * a, a)`로 내보냄).
- 라이선스: cool-retro-term, HarlequinVG gameboy_shader는 GPL이라 코드를 가져오지 않습니다. 인터넷에서 받은 셰이더나 코드는 참고만 하고 실행하지 않습니다.
- 프로젝트가 Dropbox 안이면 동기화 중에 파일 쓰기가 실패할 수 있습니다. 그러면 동기화를 잠시 멈추고 다시 합니다.

## PyKaki와 맞출 때

- 형식이 바뀌면 [LINK.md](LINK.md)를 고치고, PyKaki 저장소의 `docs/LINK.md`도 똑같이 고칩니다.
- PyKaki의 저장 형식 이름(`renpy-flow`, `.flow.json`, IndexedDB `renpy-flow-editor`)은 바꾸지 않습니다.

## 버전 올리기

같이 고치는 곳:
1. 엔진의 `VERSION`
2. 그 폴더 `README.md`의 "N에서 바뀐 점", 필요하면 "옮기기"
3. `docs/CUSTOM_GUIDE.md`, `docs/SPEC.md`
4. `CHANGELOG.md`, `README.md`의 버전

배포 전 확인:
- `.rpyc`, `*_layout.rpy`가 들어가지 않았는지 (`.gitignore`가 막음)
- `stage_config.rpy`가 배포 값인지 (`stage.bg_tag = [ "bg" ]`)
- `game/` 폴더만 새 렌파이 프로젝트에 넣고 Lint와 실행
